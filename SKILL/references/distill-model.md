# 模型蒸馏：轻量索引 → 可运行骨架 → TODO 驱动的逐模块实现

> 适用：把外部 C/C++ 模型、生成代码或特定平台实现转成可追溯、可验证的 Orpheus 图。
> 目标是完成模型，不是产出越来越厚的分析报告。自顶向下建立/展开结构，逐模块实现与验证，自底向上完成集成。

## 0. 必须遵守的推进原则

1. **先骨架、后细节**：先恢复层次、数据接口与连接，未实现边界用通用占位模块；不要先逐行理解整个模型。
2. **按索引局部读取**：第一轮只取得搭骨架所需事实。公式、系数、边界条件在实现该模块时深入；禁止无新证据地重复扫描全部源码。
3. **调用关系不是数据连接**：调用树帮助拆分，数据读写、状态与时序决定图边。函数可先作为结构节点，不强制一函数一原子 C 组件。
4. **每个工作单元必须闭环**：留下实现与测试证据，或可执行的阻塞结论；同步节点 TODO 与权威索引，不用“继续分析”代替推进。
5. **骨架可运行不等于模型已实现**：透传、置零及受其影响的下游输出不能证明外部模型等价。
6. **局部阻塞不停止全工程**：明确记录后继续无依赖的模块。完整请求必须处理全部开放 TODO；不能以“索引完成/局部切片跑通”结束。

## 1. 首轮：锁定范围并建立轻量权威索引

先确认入口、目标平台、源码版本、模型输入输出和最终验收标准。固定源文件 SHA-256，路径用项目可恢复的相对索引；不只存本机绝对路径。

索引可用工程内 YAML，必要时使用已有 Algorithm IR。**只有一份算法事实权威来源**；人读说明/覆盖报告由它投影，不重复维护多套事实。

每个模块的首轮最低记录：

| 项 | 内容 |
|---|---|
| 定位 | 稳定 ID、父模块、用途；相对源路径、符号/代码区域、版本/hash |
| 结构 | 调用者、被调用者和调用位置；重复调用的实例身份 |
| 数据 | 输入/输出、类型、shape、通道顺序；生产者与消费者 |
| 时序 | 已知 Task/TID、采样率、块长、触发关系；状态归属与 init/reset 入口 |
| 恢复 | 对应工程节点、TODO id、下一步读取入口、未知项 |

首轮允许 unknown，必须区分“尚未检查”“证据缺失”“框架不支持”。**不要为满足完整 IR 而猜值，也不要把全模型六门禁全填完作为搭骨架的前提。**

复杂多 Runtime/TID、混合 bus、事务与跨域语义逐步纳入严格 Algorithm IR；索引完整性校验在对应事实补齐时执行。现有 `index-validate/index-generate` 需要完整 IR，不是轻量首轮的强制前置命令。

## 2. 从源码层次建立图骨架

### 2.1 模块与实例

- 函数/子系统先形成层次；平铺代码按数据流、循环、状态归属划分稳定代码区域。
- 业务模块用目录 composite 包；能继续拆分的占位节点替换成 composite，其子节点继续占位。
- 同一函数不同调用位置可能对应多个实例。必须确认各自状态与参数；共享状态不能因拆图而复制。
- 一个函数可以落成多个标准组件；只服务于同一算法的辅助函数可以合成一个原子组件。保留源到图的多对多映射。
- 初始化、系数更新、复位、参数更新等不一定是音频节点，但必须建立索引和实现归属。

### 2.2 连线依据

依据实际 buffer 的读写建立数据流，查看生产者和消费者，不只读函数名/签名。处理原地修改、指针别名、全局变量、条件/循环、反馈及调用顺序。

- 画布使用标准 `graph.connections` 音频边与 `control_connections` 控制边，不发明 UI-only 关系线。
- 音频 shape 是 `[channels, frames]`；words/bytes 是物理布局，不是通道格式。
- 参数控制链的下一块提交不能冒充同一块内立即更新。
- 跨 Task 音频要经过 `async_bridge` 或允许的 `rate_sync`；变速组件不能单独代替 Task bridge。
- 同 Task 数组控制使用 typed BULK、shape、足够槽容量和目标 double bank；跨 Task/Runtime 控制、event、混合事务须有对应 bridge 契约。
- 总线 offset、atomicity、sequence、epoch、validity、交换延迟留在索引；未 lowering 的关系保持 blocker，不能伪装成可执行边。
- 图内反馈、任意相位、事件或事务等若不能由当前契约准确表达，提交框架能力缺口；不要擅自用任务桥、延迟或浮点数改变语义。

## 3. 通用占位模块：不为每个空节点编写 C

### 3.1 两类占位必须分清

| 类型 | 用途 | 执行能力 |
|---|---|---|
| `orpheus.builtin.placeholder` | 人工或 AI 搭建可运行音频骨架；固定通用源码 | 显式配置路由透传/置零，有编译警告、运行日志和画布徽标 |
| `package_type: placeholder` | 尚无合法模拟契约的研究边界；已有 Algorithm IR 投影 | 仍由 Compiler 拒绝，不自动转成透传 |

选择可运行占位就是显式选择模拟语义，不是通过 debug_mode 绕过算法未实现保护。

可运行占位的 `interface` 是 JSON 数组，每端口有唯一 `id`、`direction: input|output`、`channels: 1..64`；每方向最多 32 个端口，至少一个端口。UI 参数面板提供表格式编辑，不必写源码或手工编 JSON。

当前只支持 **同 Task、f32 音频**，采样率/块长遵循现有编译器推导；不模拟控制/event、FFT 格式变换、变速、事务或硬件延迟。

```yaml
- id: front
  component: orpheus.builtin.placeholder
  params:
    interface: '[{"id":"mic","direction":"input","channels":2},{"id":"audio","direction":"output","channels":2},{"id":"monitor","direction":"output","channels":1}]'
    mode: passthrough
    routes: "0,-1"
  todos:
    - id: implement-front
      title: 抽取前处理并验证
      status: pending
      source_ref: "analysis/index.yaml#front；src/model.c:FrontProcess"
      source_hash: "源文件 SHA-256"
      intent: 双通道前处理；旁路保持通道顺序
      next_step: 读取 FrontProcess 及调用点，检查滤波系数和独立状态，优先匹配 FIR/IIR
      acceptance: 默认、非零、跨块、reset 与参考 golden 对拍，并验证动态/生成一致
      blocker: ""
```

`routes` 按输出声明顺序列出 **从 0 开始的输入序号**，`-1` 置零。透传必须通道匹配且输入已连接；不隐式混音、重采样、补通道或把断线静默当零。`mode: silence` 明确将全部输出置零。只有输入的 sink 可用空 routes；只有输出的 source 可用 silence 或 `-1` 路由，但占位组件不是时钟源。

接口未知或无法合法模拟的节点保持严格占位。允许先运行独立切片，不要求靠猜测让所有未知路径一次跑通。

### 3.2 TODO 是工作接口，不是装饰性注释

TODO 放在**节点的 `todos` 数组**，不是组件参数或仅在笔记中；属于工程实例/定义，替换组件时保留同一节点 ID 和 TODO。输入输出名称也尽量保持稳定，改变时显式更新边界。

每项必须有 `id/title/status`，蒸馏任务还必须填写：

- `source_ref`：索引 ID、相对源码路径和符号/代码区域；行号仅辅助，不能单独定位。
- `source_hash`：源版本/hash；版本变化后失效的分析和 golden 要重验证。
- `intent`：预期功能及重要状态/时序约束。
- `next_step`：下一次从哪里读、具体做什么，不写泛泛的“继续研究”。
- `acceptance`：可执行的验收条件；完成后附测试/证据位置。
- `blocker`：未决事实、影响范围、已尝试检查及解阻条件。

状态：`pending → in_progress → done`，遇阻塞记 `blocked`；候选已接入但未验证保持进行中，不能标 done。细分模块时，把未完成责任分配给子节点 TODO，并留下父子索引，不能悄悄删除原任务。

### 3.3 每轮开始与结束都枚举 TODO

```powershell
python -m orpheus_core.cli todos workspace\my_model --json
python -m orpheus_core.cli todos workspace\my_model --all --json
python -m orpheus_core.cli todos workspace\my_model --check
```

- UI 左侧 **TODO**：查看并定位节点，包含未保存编辑；参数面板可编辑 TODO。
- API：`GET /api/projects/{name}/todos?include_done=true`。
- 清单覆盖主图及全部已加载子图定义，**包括未实例化定义**；共享定义只列一次，位置为 `view/node#todo-id`，不是扁平运行实例计数。
- 严格占位的 manifest blockers 也列出；占位节点没有开放 TODO 时会自动暴露未实现项，不能靠删任务或标 done 隐藏。
- `--check` 有开放项时返回 1，可作为交付门禁；它查结构化任务，不扫描任意源文件中的 TODO 注释。外部文本待办须归并到权威索引/节点 TODO。

## 4. 按 TODO 自顶向下展开、逐模块抽取

每次选一个可推进模块，先更新为进行中，然后只读取该模块、必要调用点和直接依赖。

按顺序选择：

1. **已有标准组件**：搜索 builtin、README 和测试；匹配语义、状态更新、布局和边界，不只匹配名称。
2. **标准组件组合**：用 composite 表达串并联、滤波、矩阵、路由、延迟等；大模块先继续拆分。
3. **补充通用组件**：算法明确可复用时新增，配 README、数值测试和双路径验证。
4. **自定义代码组件**：项目独有或组合代价不合理时采用；简短记录选择理由，不为证明“不可泛化”无限分析。

平台优化可替换为标准实现，但检查定点缩放、舍入/饱和、系数顺序、状态布局、流水延迟与更新时刻。加速 FIR 的名字不是与通用 FIR 等价的证据；近似必须标记 approximation 并明确容差，不能静默接受。

常见候选（必须核实具体参数与数值语义）：

| 源码模式 | 候选 |
|---|---|
| FIR / 多级 IIR / biquad | `fir` / `iir_bank` / `biquad`、`biquad_bank` |
| FFT / IFFT | `rfft` / `ifft`（检查归一化、半复数布局和点数） |
| 混音 / 矩阵 / 通道路由 | `mixer` / `matrix_mul` / `deinterleave`、`interleave` |
| 增益、斜坡、延迟 | `gain`、`gain_ramper`、`delay` |
| 查表、限幅、观测 | `interp_lut`、`saturation`、`probe_*` |

长系数用 `$resource` + shape/hash，提取脚本可重跑；运行期系数槽声明 `bulk_slots`。签名参数需 `restart_required`。控制目标/源遵守 `bindable/control_source/shape/maps_to` 契约。禁止把未知参数塞进组件伪装已支持。

## 5. 验证伴随实现，不阻止候选尽早集成

保留六维验收，但它们是**逐模块补齐的验证账本**，不是所有模块开工前的前置大表：

| 维度 | 验收事实 |
|---|---|
| boundary | 输入输出、shape、通道顺序、单位与旁路 |
| schedule | Task、触发、读写顺序、交换延迟 |
| algorithm | 公式、分支、反馈、饱和、边界条件 |
| state | 初值、共享/独立归属、跨块更新、reset |
| parameters | 默认值、布局、更新策略、资源/hash |
| golden | 默认、非零、极值、跨块、reset、bypass 的参考对拍 |

候选实现可以替换可运行占位并进入研究工程，但 TODO 必须保留进行中，索引标明未验证；六项通过后才能标记模块 verified/done。无占位不自动等于完整实现。

- **外部参考对拍**：事先确定逐位相等或数值容差，记录最大误差等实际指标；没有可运行参考时记录缺证据，不能自证等价。
- **动态/生成一致性**：按仓库要求逐字节一致；二者相等只证明内部路径一致，不证明还原正确。
- **增量集成**：先模块，再边界/子系统，再完整模型；覆盖时序和状态，不只测一块零输入。
- 含桩的路径是骨架验证。真实模块的局部 golden 应来自独立真实输入/参考，不用桩污染的系统输出验收。
- 初始化、复位、禁用、参数更新和目标部署约束同样计入覆盖，不能只覆盖 process 主路径。

## 6. 断点恢复、生成边界与阻塞

工程保留权威索引、必要 `analysis/`、参数提取脚本与资源、golden/测试及结果摘要。报告按增量写，不每轮重述全模型。

**手工实现与生成投影必须隔离**：现有 `index-generate` 重建投影时会清理其拥有的 `components/`。手写源码、TODO 和映射放在非生成路径；已有工作必须先持久化到权威输入或人工工程，不能靠再生成后重贴。不要直接在会被覆盖的目录蒸馏。

下一轮恢复顺序：枚举 TODO → 校验相关源 hash → 读索引和上一条测试证据 → 继续下一步。源未变化且证据有效时，不重复分析已验证模块。

阻塞分为证据缺失、语义未决、框架缺口、验证失败。每条记录位置、影响、已做检查和解阻条件；重要歧义及时报告，不私自选一个“看起来能跑”的行为。已确认语义但框架表达不了时，给出最小代码/数据关系、预期时序与当前失败点，供框架改进；不要靠伪边或静默透传掩盖。

## 7. 完成条件与旧格式

用户要求完整蒸馏时必须继续处理所有可推进 TODO。只有：

- 可运行/严格占位均清零；
- 全部必需模块、状态和参数有覆盖与验证证据，未验证候选/近似没有冒充完成；
- 完整系统参考对拍、动态/生成一致和约定目标平台验证通过；
- 清单 `todos --check` 通过，索引、实现、测试和恢复说明一致；

才能声称完整完成。若剩余项全为真实 blocker，交付明确阻塞清单与解阻动作，不能称为“完整模型已蒸馏”。

旧 `model_tree/subcomponents/sub:` 和 `/distill` 一键导入只作兼容。旧导入器的未知块 ID 也是 `orpheus.builtin.placeholder`，现在解析为真正的通用桩，但**默认接口不证明原模型接口**，仍须补 TODO、检查接口/路由与时序；历史 `downrate + embed_out` 死路不能证明控制或跨 Task 行为正确。新工程优先目录组件包与裸组件 ID。
