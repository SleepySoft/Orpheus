# 扫频响应记录

`orpheus.builtin.sweep_record` 将每次实际交付的首声道能量分配到配置频率箱，
同时逐位直通全部音频；它不产生激励、不测相位，不是标准传递函数或 WAV 录制。
滤波器瞬态、延迟和块跨箱会影响结果，不能直接把曲线当作严格稳态增益测量。

## 接口与真实调用

`in` 是唯一驱动入口，`out` 驱动编号为 1。
每次正帧调用独立推进实际帧数与本地时间，同拍重复交付不合并、不按 Task 拍数去重。
先提交统计再 emit，下游失败不回滚；完成后继续直通，不继续采集。
输入/输出均须绑定并覆盖本次帧数；支持完整原地，拒绝部分重叠和私有状态别名。
零帧不推进、不交付；采样率须有效并与 prepare 一致，保留 ABI 的 double 精度。

## 设置

| 接口 | 默认值 | 规格 |
|---|---|---|
| `start_freq` / `end_freq` | 20 / 20000 Hz | 1～20000；支持升频、降频和相等频率 |
| `duration_s` | 0 | 0～300 秒；正值按实际样本计时，0 等待静音收尾 |
| `log_scale` | true | 对数/线性频率轴 |
| `bins` | 64 | 8～256 |
| `channels` | 1 | 1～32；影响音频签名，只分析第 0 通道 |

设置均需重启。图含 `sweep_gen` 时仍沿用编译器的扫频参数注入规则；
**没有发生器注入且 duration_s=0 时，没有已知扫频时长，频率保持起点、只累计首箱**，
不猜测扫频轨迹。激励与采集时间线必须由工程正确连接。
相等起止频率的采集也固定首箱，避免原来 0/0 分箱的不确定行为。

## 数学与观测

当前调用起始本地时间为 `t`：对数频率 `f0*(f1/f0)^(min(t,duration)/duration)`，
线性为 `f0+(f1-f0)*min(t,duration)/duration`，随后映射至最近的箱。
整次调用计入该箱；首声道样本先转 double 再平方求和，
再转 f32 累加能量，保留原 `sqrtf(acc/(float)count)` 的 RMS 次序。

- `sweep`：只读 512 项 float 探针；`[0:256]` 是频率，
  `[256:512]` 是 RMS 幅度，各自仅前 bins 项有效，未用位置为零。
  **不是先 bins 项频率再紧接 bins 项幅度**；UI 使用相同固定 256 项跨度。
- `progress`：未完成时为已采集箱数/bins；完成后为 1。
- `current_freq`：最后一次被分析调用的起始频率，完成时不强制改为终点。

达到配置时长，或有声之后低于历史最大调用 RMS 的 2% 连续至少 0.25 秒，采集完成。
静音阈值为 `ceil(sample_rate/4)` 个样本，低速/非整数速率不会因取整为零而立即完成；
初始静音不当作已有扫频结束。帧计数、静音帧和每箱样本数采用 64 位，
溢出/不变量错误在任何统计或输出修改前拒绝。
reset 清本地时间、能量、计数、幅度、进度及当前频率，保留配置和频率轴。

## 独立生成与验证

先保存唯一 `component.yaml`，再由 `scripts/generate_component.py` 校验/生成。
原生冒烟验证独立线性时间/能量预期、变长调用、错误后继续、完成后直通、
完整原地/部分别名、坏容量/采样率、计数溢出、零帧/reset、恒频及 2.5Hz 静音收尾。
`test_sweep_record_interfaces.py` 覆盖四图/四入口的线性/对数降频、32 通道、
256 箱、恒频、自动静音完成、固定跨度完整曲线与名称/ID只读探针。
512 项探针占 2048 字节，符合 Bridge Core Profile。
