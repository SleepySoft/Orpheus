# orpheus.builtin.sweep_record — 扫频记录

## 功能

频率响应测量组件：与 `sweep_gen` 成对使用。它把输入音频原样直通，同时用与扫频发生器**完全相同**的频率公式反推"当前时刻发生器在扫哪个频率"，把每个块的输入能量（第 0 通道 RMS）累计到对应的频率箱（bin）里；扫频结束后得到一条 `频率 → 幅度` 曲线，通过 `sweep` 探针上报，UI 节点本体直接画出频响图。

一句话：把 `sweep_gen` 发的扫频信号穿过被测链路（滤波器、扬声器+房间、编解码器……），`sweep_record` 告诉你链路在每个频率上衰减/增强了多少。

## 参数

| 参数 | 类型 | 默认值 | 范围 | 更新策略 | 说明 |
|---|---|---|---|---|---|
| `start_freq` | float | 20.0 | 1.0–20000.0 | restart_required | 起始频率（Hz），须与发生器一致。 |
| `end_freq` | float | 20000.0 | 1.0–20000.0 | restart_required | 结束频率（Hz），须与发生器一致。 |
| `duration_s` | float | 0.0 | 0.0–300.0 | restart_required | 扫频时长（s）；**0 = 自动跟随图中的扫频发生器**（编译器注入），手动设置可提前截断。 |
| `log_scale` | bool | true | — | restart_required | 对数/线性分箱，须与发生器一致。 |
| `bins` | int | 64 | 8–256 | restart_required | 频率箱数量（曲线点数）。 |
| `channels` | int | 1 | 1–32 | restart_required | 通道数，影响端口签名；只分析第 0 通道。 |

> 正常情况下只需设 `bins`：编译器会把图中 `sweep_gen` 的 `start_freq` / `end_freq` / `duration_s` / `log_scale` 自动注入所有 `sweep_record` 节点，保证频率轴与发生器严格一致（参数不一致会导致提前完结或频率映射错乱）。

### 工作原理

1. 每来一个块，用与发生器相同的公式计算当前时刻的扫频频率：`log: f0×(f1/f0)^(t/dur)` 或 `linear: f0+(f1−f0)×(t/dur)`。
2. 把该频率映射到最近的箱（箱中心频率按对数或线性均匀分布在起止频率之间）。
3. 累加这个块的样本能量（第 0 通道平方和）到该箱，并实时更新该箱的幅度 `sqrt(能量和/样本数)`——所以曲线是**边扫边长出来**的。
4. 完结条件（先到先触发）：累计时长达到 `duration_s`；或检测到输入静音——发生器扫完后输出 0，当块 RMS 低于历史峰值的 2% 并持续 0.25 秒即判定结束。
5. 完结后 `done=true`，各箱幅度定稿为该箱内全部样本的 RMS。

### 探针

| 探针 | 类型 | 说明 |
|---|---|---|
| `sweep` | string | JSON 对象：`{"freq":[...], "mag":[...], "done":bool, "progress":float}`，`freq[i]` 为第 i 箱中心频率（Hz），`mag[i]` 为该箱 RMS 幅度。 |
| `progress` | float | 进度 0~1 = 已采集箱数 / 总箱数（频率覆盖度）。 |
| `current_freq` | float | 当前分箱对应的频率（Hz），可与发生器的 `current_freq` 对照。 |

### 读数怎么解读

- `mag` 是线性 RMS 幅度，不是 dB。直通链路（无衰减）且发生器 `amplitude=0.7` 时，曲线读数 ≈ 0.7 / √2 ≈ 0.49。
- 换算增益 dB：`20 × log10(mag_输出 / mag_参考)`。直接在节点图上看即可——UI 已转成 dB。
- 曲线上没扫到的箱 `mag=0`（UI 不参与坐标范围）；`done=false` 时曲线还在生长，属正常现象。

## 端口

| 端口 | 方向 | 说明 |
|---|---|---|
| `in` | 输入 | 被测链路的输出音频，`channels` 通道。 |
| `out` | 输出 | 与输入完全一致（直通，可继续接 `wav_out` 落盘）。 |

## UI 行为

UI 节点本体（`nodeWidgets.js` 的 `SweepPlotWidget`）读取 `sweep` 探针画频响曲线：横轴为对数频率轴（自动用 `freq` 数组取 log10），纵轴为 dB（`20×log10(mag)`，只统计已采集的箱）。扫频进行中能看到曲线从左到右逐段补全，画完即定型。

## 注意事项

- 全部参数 `restart_required`，运行时不可改；起止频率、时长、对数开关必须与发生器一致（默认交给编译器自动注入，别手填）。
- `duration_s=0` 表示自动模式：不按时间截断，靠"发生器扫完 → 输入静音 0.25s"兜底完结，时长由编译器注入跟随发生器。
- 只分析第 0 通道，但所有通道原样直通。
- 测量的是"链路的稳态幅度响应"：每箱只取 RMS，不含相位；块跨越箱边界时整个块计入块起始频率对应的箱，块越小分箱越准。
- 实时安全：`process` 仅直通拷贝与定长累加，无分配、无 IO；JSON 编码在非实时线程（探针轮询）执行。

## 典型用法

离线频响测量（参考 `examples/sweep_record_plot.yaml`）：

```
sweep_gen ──► biquad(被测滤波器) ──► sweep_record(bins=64) ──► wav_out
```

运行结束后看 `sweep_record` 节点上的曲线：平直段是通带，下弯处是截止频率，陷波/峰起一目了然。离线运行时长由 `sweep_gen.duration_s` 决定，保证整条扫频被完整记录。

## 实时安全

`process` 无内存分配、无阻塞、无 IO；能量累计为定长数组操作，完结判定为常数时间比较。
