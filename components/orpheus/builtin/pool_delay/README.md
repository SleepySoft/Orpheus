# 共享池声道延迟

`in` 每次实际到达后，算法直接交付 1 号 `out`，同 Task 多次到达不合并。
配置与类型化壳由独立 `scripts/generate_component.py` 生成；
算法仅在 prepare 分配共享池，实时处理不分配内存。

- 通道位置由当前延迟前缀和决定，允许池地址相互重叠。
  必须先读取所有通道，再按声明顺序写回；后通道可以覆盖先通道。
  变长重新解释旧池，不等同于每通道独立延迟线。
- `delays_i32` 是真实双缓冲 int32 数组，活动数量等于 channels，
  槽范围按实例限制为 `[0, pool_size_samples]`，不是全局最大容量。
  默认全零，也可在配置中提供完整 64 项初值（非活动项补零）。
- 禁用时仍验证音频签名和容量，逐位输出干声、冻结整个池与游标。
  reset 清池和游标，保留延迟与使能；下游失败不回滚已处理历史。
- 拒绝短载荷、输入输出重叠及私有池别名。
  保留有效零帧事件直接交付的行为，池和游标不变。
- 候选配置先纯校验，失败保留旧池、游标和参数。

回归见 `tests/pool_delay_smoke.c`、`orpheus_core/tests/test_pool_delay.py`
与 `orpheus_core/tests/test_pool_delay_interfaces.py`；包含独立共享池参考、
IEEE 位型、最大 64 通道/192000 样本池和四入口真实运行。
