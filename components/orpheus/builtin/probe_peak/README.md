# orpheus.builtin.probe_peak — 峰值表

## 功能

最轻量的峰值监控组件：把输入音频原样直通，同时逐样本扫描当前 process 块内所有通道的绝对值最大值，通过 `peak` 探针上报。适合观察链路中某一点的瞬时峰值、检测削波（>1.0）、或给自动化测试做"有没有爆音"的断言。

## 参数

| 参数 | 类型 | 默认值 | 范围 | 更新策略 | 说明 |
|---|---|---|---|---|---|
| `channels` | int | 2 | 1–32 | restart_required | 通道数，改变后需重新编译（影响端口签名）。 |
| `peak` | float | 0.0 | — | immediate | 当前块峰值（readback，只读）。 |

### `peak` 上报的是什么

计算公式：

```
peak = max(|x[i]|)   （i 遍历当前块的所有帧 × 所有通道）
```

- 它是**当前块**内所有通道中的最大绝对样本值，不做任何平滑或保持。
- 线性刻度，不是 dB。正弦幅度 A 时 peak ≈ A；>1.0 表示超出满幅（削波）。
- 块边界处读数会跳动：安静块可能报很小的值。需要"表针缓慢回落"的效果请用 `level_detect`（mode=0，带 release）。

### 与电平表（probe_rms）的区别

- **峰值表**：看瞬时能到多高，回答"会不会削波"。对突发、瞬态敏感。
- **电平表（probe_rms）**：看能量平均值，回答"听起来多响"。更接近响度感知。

同一块音频：短促的鼓点 peak 很高但 rms 一般；持续的白噪声 rms 高但 peak 未必顶天。两者常并排使用。

## 端口

| 端口 | 方向 | 说明 |
|---|---|---|
| `in` | 输入 | 输入音频，`channels` 通道。 |
| `out` | 输出 | 输出音频，与输入逐样本一致（零延迟直通）。 |

## UI 行为

UI 节点本体（`nodeWidgets.js` 的 `ProbePeakWidget`）读取 `peak` 探针，显示为一条电平条（LevelBar），运行后实时刷新；未运行时显示"运行后显示峰值"。

## 注意事项

- `peak` 没有保持/释放逻辑，只在当前块结束时更新一次；块越长，刷新越慢。
- `channels` 是 `restart_required` 且影响端口签名，运行时改不动。
- 实时安全：`process` 只做一次遍历，无内存分配、无 IO、无三角函数。

## 典型用法

```
main_out ──► probe_peak ──► wav_out
```

放在最终输出前，运行时盯一眼峰值条即可确认整条链路没有削波，同时不影响 WAV 写入。
