# 宿主音频缓冲接口

接口配置由独立脚本校验和生成；算法只在真实处理完成后交付1号 `out`。
`in` 是音频驱动入口，`tick` 是无PCM的纯触发入口；
每次到达独立处理，不等待其它分支或补调。
宿主写入资源不自动触发组件，仍须由所属Task或上游推进。
纯Task/分频源连接tick，不伪造音频载荷。

- mode=0：无上游时消费宿主写入的 `samples` 和 `ready`；
  有上游时复制完整输入，禁止同时置ready。缺块明确报错，
  missing_blocks饱和递增，不用静音代替输入。
- mode=1：必须有完整上游输入，复制到samples并置valid，供宿主读取。
  ready的参数设置仅允许mode=0。
- samples外部资源键由audio_storage接口绑定私有存储，
  有效形状为 `[config:frames, param:channels]`，物理容量8192个f32。
  配置零帧、超容量或非零初始交付状态拒绝，失败不覆盖旧状态。
- 注册统一服从接口声明：samples始终声明双Bank，ready/valid/缺块探针
  均有稳定注册槽，不再按mode改变注册表。活动宿主绑定仍按mode互斥，
  mode=1拒绝通过参数setter提交ready；只读探针不能通过setter修改。
- NULL图输出仍消费/捕获输入并交付事件；零处理量不推进、不交付。
  reset清空完整物理缓冲及交付状态。下游失败不回滚已消费/捕获的块。
- 仅支持完整交错f32块，拒绝不足载荷及输入/输出/整个State之间的重叠，
  包括输入与输出精确原地。

旧宿主实现头暂由尚未迁移的buffer_source使用，已不参与本组件构建。
