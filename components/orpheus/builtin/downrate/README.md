# orpheus.builtin.downrate — 音频组块器

## 两个独立入口

将 `factor` 个完整小块逐样本拼接为一个大块，采样率不变，不滤波、不补零。

- `in`：`process: true`，每次追加 `input_frames` 帧到私有存储，**写满也不调用下游**。
- `tick`：纯触发、`process: true`，读取完整大块，消费水位后显式交付 1 号 `out`。
- `out`：`input_frames * factor` 帧，`drive_port_no: 1`；只有算法处理 `tick` 时交付。

写入与读取的频率、先后顺序由上游算法及读取触发链安排，框架不匹配频率、不补调。
`factor` 仅决定形状与容量，不再声明 `scheduling.divisor`，不是调度分频器。
同一 Task 内多次写入/读取也逐次执行，不按 Task 去重。

## 参数与探针

| 接口 | 默认值 | 范围 | 说明 |
|---|---|---|---|
| `input_frames` | 32 | 1～65536 | 每次写入的完整小块帧数 |
| `factor` | 4 | 1～64 | 大块包含的小块数 |
| `channels` | 2 | 1～32 | 交错 f32 通道数 |
| `available_frames` | 0 | 只读 | 尚未消费的帧数 |
| `underflows` | 0 | 只读 | 读取不足一个完整大块的次数，饱和计数 |
| `overflows` | 0 | 只读 | 未读数据可能被覆盖的写入次数，饱和计数 |

前三项均为影响签名的 `restart_required` 参数，不能运行期修改。
探针初值必须为零，不能通过 setter 修改。

## 载荷、时间与错误

- 显式端口块长描述交付载荷，不覆盖节点的处理量子 `ctx.frame_count`。
  消费大块的接口也应声明对应块长，不能把 Task 的小块默认长度当作大块签名。
- 部分批次的后续写入必须具有相同 epoch、连续的绝对帧位置；
  中途 `DISCONTINUITY`、时间不连续及不完整大块边界的 `EOS` 均明确拒绝。
- 输出时间使用第一小块的 `frame_index/epoch`，质量标志聚合各小块；
  不使用读取 `tick` 的时间冒充数据时间。
- 欠载及未读覆盖报错，不清空已有数据、不伪造静音，也不等待会合。
  非法载荷、时间及 State/私有存储别名在拷贝前拒绝。
- 消费水位在调用下游之前清零；下游失败不重放已经消费的大块。
  零帧调用不推进、不交付。
- `reset` 清水位、探针与时间；部分批次不能跨重置拼接。

## 调用示意

同一上游算法每次发布一个 7 帧小块，并在每第四次发布后显式触发读取：

```text
上游算法 ──音频交付──► downrate.in（input_frames=7, factor=4）
         └─每第四次发布后的纯触发──► downrate.tick
                                     └─out──► 声明28帧载荷的消费者
```

前三次发布没有下游调用，第四次写满仍不调用下游；
随后到达 `tick` 才交付 28 帧。调用顺序是上游算法的责任，不是水位的副作用。
若读取先于写满，则返回欠载错误。

## 生成与实时安全

声明位于 [component.yaml](component.yaml)，独立生成脚本生成 `generated/`，
手写算法位于 [user/algorithm.c](user/algorithm.c)。
私有存储仅在 `prepare` 分配、`destroy` 释放；
非法配置不破坏旧状态，分配失败清理后可重试。
实时入口只有有界拷贝、时间检查与计数器更新，无分配、锁或 IO。
