# 音频拆块器

输入与读取是两个独立驱动入口：

- `in`：接收完整的 `output_frames × factor` 帧，复制到私有存储，
  不交付out。旧块尚未读完时拒绝覆盖并累计overflows。
- `tick`：纯触发，每次读取output_frames帧并显式交付1号out。
  没有完整小块时明确报错并累计underflows，不跳过调用、不补静音。

水位不触发下游；生产者、触发源及调用顺序由工程/上游算法明确安排。
同Task内连续到达分别处理，不补调或去重；本组件不提供跨Task并发安全。
factor只是大/小块形状比，不是调度分频。output_frames默认32，
另有channels/factor重启参数；输入签名显式等于三者声明的形状，
不再从旧全局调度器的调用次数猜测何时快照大块。

数据在in调用内完成快照，上游随后重写自己的Buffer不会覆盖待读数据。
读取时间来自原始大块的frame_index加游标，epoch保持；
DISCONTINUITY只带在首片，EOS只带在末片。
读取状态在交付前推进，下游失败不重放已消费片段。
零帧不推进、不交付；reset清空私有存储、水位及饱和计数。
输入/输出不得与整个State或私有存储重叠，时间位置加法溢出明确拒绝。

私有存储只在prepare分配、destroy释放。非法候选不触碰旧资源；
资源重建分配失败会清理，必须成功重试prepare后才能处理，不假称回滚旧历史。
运行期不允许直接修改重启参数和只读探针。

这是有意移除的旧行为：前factor-1次调用不再输出伪造的零块，
大块发布不再兼作小块读取；已有工程须明确连接tick，并声明output_frames。
