# orpheus.builtin.interp_lut — 参数查表插值

## 功能

一维线性插值查表器：给定一组 `(x_axis, y_axis)` 数据点，对输入 `x` 进行插值得到 `y`。音频本身原样直通，主要用于控制信号链路的“映射函数”——例如把车速、噪声级、旋钮位置等非线性映射成目标增益或阈值。

## 参数

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `x_axis` | string | "0, 1" | 初始化横坐标文本，逗号或空白分隔；不是运行期 BULK 槽。 |
| `y_axis` | string | "0, 1" | 初始化纵坐标文本，逗号或空白分隔；不是运行期 BULK 槽。 |
| `x` | float | 0.0 | 当前输入值，可实时设置。 |
| `y` | float | 0.0 | 当前插值结果（readback，只读）。 |
| `history` | string | "[]" | 最近的 `y` 值历史（readback，只读）。 |
| `channels` | int | 1 | 音频通道数，改变后需重新编译。 |

### `x_axis` / `y_axis` 的真实含义

两条列表定义了一个分段线性函数 `y = f(x)`。例如：

```yaml
x_axis: "0, 20, 80, 120"
y_axis: "0, 0.1, 0.6, 1.0"
```

表示：

- 车速 0 → 增益 0
- 车速 20 → 增益 0.1
- 车速 80 → 增益 0.6
- 车速 120 → 增益 1.0

中间值按线性插值；小于最小 `x` 取第一个 `y`，大于最大 `x` 取最后一个 `y`。

### `x` 与音频的关系

该组件的 `in/out` 音频端口只是让它能挂在信号链里；实际插值计算只依赖 `x` 参数。通常把上游 `level_detect` 的 `level` 或外部控制值写入 `x`，再读取 `y` 作为其他组件的参数。

## 端口

- `in`: 输入音频，`channels` 通道（直通）。
- `out`: 输出音频，与输入完全一致。

`in` 是驱动入口，`out` 是 1 号驱动出口；每次实际到达计算一次 `y`，
将结果加入历史后同步交付，同 Task 的重复到达不去重。
保留原控制语义：有效 Buffer 的零帧到达仍更新结果/历史并交付，
不是靠音频长度决定是否发生控制事件。

## 注意事项

- 两轴必须非空、等长、最多 256 点；X 严格递增，
  数值及相邻差值必须能表示为有限 f32。非法 CSV、空项、尾逗号、
  非有限值、长度不匹配和重复/逆序 X 明确拒绝，不再截断或静默造默认表。
- 两份初始化文本各最多 8191 UTF-8 字节，不作为运行期槽的回读；
  原先 `kind: bulk` 标签没有对应真实数组槽，现按初始化字符串声明。
- 修改 `x_axis` / `y_axis` 后需要重新编译。
- `x` 可实时变化，范围为 [-1e9, 1e9]；每次实际到达计算，
  保留 f32 减法、除法、乘法与加法顺序。
- `y/history` 是只读探针，不能作为参数写入；历史保存最近 64 次到达，
  按时间顺序输出 `%.4g` JSON 数组。prepare/reset 后为空数组 `[]`；
  reset 同时将 `x/y` 清零，但保留表。
- 音频逐位直通，支持精确原地，拒绝短载荷及部分重叠。
  非法候选保留原表、控制值和历史；下游失败不回滚已记录结果。
- 实时安全，process 内无内存分配、无三角函数。

接口以 `component.yaml` 为事实源，经独立脚本生成壳，
手写实现保存在 `user/algorithm.c`。

## 典型用法

```
noise_level_detect ──► (y as gain target)
signal_gen ──► gain(gain_db = -interp_lut.y * 20) ──► out
```

用噪声电平查表得到一个 0~1 的抑制量，再把它映射成 dB 衰减值控制 `gain`，实现按噪声自动调节音乐响度。
