# orpheus.builtin.probe_spectrum — 频谱分析仪

## 功能

实时频谱监控组件：把输入音频原样直通，同时把第 0 通道写入长度为 `window_size` 的环形缓冲；每攒满一窗样本，对整窗加 Hann 窗后做 radix-2 FFT，得到前半段（`window_size/2` 个）幅度谱，通过 `spectrum` 探针以 JSON 数组上报。适合观察信号的频率成分、确认滤波器效果、找啸叫/噪声频点。

## 参数

| 参数 | 类型 | 默认值 | 范围 | 更新策略 | 说明 |
|---|---|---|---|---|---|
| `channels` | int | 2 | 1–32 | restart_required | 通道数，改变后需重新编译（影响端口签名）。 |
| `window_size` | int | 1024 | 64–4096 | restart_required | FFT 点数（见下文，实际会取整到 2 的幂）。 |
| `spectrum` | string | `""` | — | immediate | 当前幅度谱的 JSON 数组（readback，只读）。 |

### `window_size` 的真实含义

- 内部使用迭代 radix-2 FFT，因此实际窗口会被取整到**不小于设定值的 2 的幂**（最小 64，最大 4096）。例如设 1000 → 实际 1024。
- 频率分辨率 = `采样率 / window_size`。48 kHz、1024 点 → 每格约 46.9 Hz；想看 20 Hz 附近的低频细节，需要 4096 点（约 11.7 Hz/格）。
- 窗口越大，刷新越慢：每攒满一整窗才分析一次。48 kHz、4096 点 → 约每 85 ms 更新一次；1024 点 → 约每 21 ms。

### `spectrum` 上报的是什么

- JSON 数组，共 `window_size/2` 个元素，第 `i` 个元素对应频率 `i × 采样率 / window_size`（0 Hz 到奈奎斯特频率）。
- 每个值是**幅度谱**：`2 × |FFT[i]| / N`，因此一个幅度为 A 的正弦波，其主峰读数 ≈ A（满幅正弦 ≈ 1.0）。不是 dB，也不是功率谱。
- 分析前对整窗乘 Hann 窗，减少频谱泄漏；代价是主瓣略展宽，相邻很近的两个峰可能糊在一起。
- 只分析第 0 通道。

## 端口

| 端口 | 方向 | 说明 |
|---|---|---|
| `in` | 输入 | 输入音频，`channels` 通道。 |
| `out` | 输出 | 输出音频，与输入完全一致（memcpy 直通，零延迟）。 |

## UI 行为

UI 节点本体（`nodeWidgets.js` 的 `SpectrumWidget`）读取 `spectrum` 探针画柱状频谱：

- **频率轴（横轴）**：线性刻度，从 0 Hz 到奈奎斯特频率（采样率/2，由编译后的节点速率推出）。注意是线性轴——低频段挤在左边，看低频请加大 `window_size`。
- **幅度轴（纵轴）**：dB 刻度，0 dB（顶，满幅）到 −80 dB（底）。安静信号的底噪通常在 −60 dB 以下；冒到 0 dB 附近的谱线说明该频率上有接近满幅的成分。

## 注意事项

- 分析触发点是"攒满一整窗"，与块边界无关；启动后第一窗出来前读数为 0。
- `window_size` 是 `restart_required`，运行时改不动；改窗口需重新编译/重启。
- 内存分配（窗口表、环形缓冲、FFT 工作区）全部在 `prepare` 完成，`process` 内无分配；FFT 在攒满一窗的那一帧同步执行，峰值 CPU 占用集中在该帧——块长很短时请注意余量。
- JSON 编码在非实时线程（探针轮询）执行，不在音频回调里。

## 典型用法

```
main_out ──► probe_spectrum ──► wav_out
```

放在均衡器/滤波器之后，直观看频响曲线有没有按预期起落；配合 `signal_gen` 输出单音，可验证谱峰位置是否等于设定频率。

## 实时安全

`process` 仅环形写入、memcpy 与（每窗一次的）定长 FFT，无 malloc/IO/锁；所有缓冲在 `prepare` 分配。
