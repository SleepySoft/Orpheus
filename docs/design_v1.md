音频框架Orpheus

1. 产品目标

构建一套清晰简洁，使用现代化理念设计的音频系统。

目标：
+ DSP 学习、音频算法实验
+ 嵌入式部署，包括传统DSP和SOC
+ 源码/Lib + metadata实现及声明组件，可视化框架组装和调参
+ 提供控制接口、调音接口、探针等机制

总结：用户通过节点连接建立音频处理系统，在 PC 上实时运行、听音、调参和观察信号，并可生成结构清晰、可独立编译的 C/C++ 工程，并提供配置和监控机制。

2. 基本概念

2.1 组件

系统采用组件化设计，每个子功能都是一个组件，一个组件可以包含其它组件，同时也能被更高层的组件包含。

组件需声明其接口，每个接口都有签名，并分为以下几类：

+ AudioPort：
-- 分输入输出，签名一致即可连成上下游。典型的音频组件通道可以配置，动态改变其接口签名。通道数不一样需经过分线器，采样率不一样须经过同步组件（见下文）。
-- 也可以接入观测器查看波型等。
-- 输出可以接多个组件（包括观测和功能组件）。

+ ControlPort：
-- Status：获取状态，通常是同步
-- Command：控制接口，同步或异步
-- Parameter：相当于Setting，主要是运行时参数，同步或异步

+ BulkPort：
-- 为大量数据优化的高速接口，通常用来传输调音数据

3.3 Editor

跨平台可视化编辑

支持节点拖放、类型化连线、参数配置、子系统嵌套、模板、撤销重做和错误定位。

界面提供三种视图：

教学视图：波形、频谱、频响、公式和信号流
工程视图：采样率、块长、任务、内存和延迟
调试视图：Probe、参数读回、CPU 和 Buffer 状态

交互强调直观、即时反馈和低学习门槛。

3.4 Components

组件化。提供混音、通道拆分合并、交错转换、重采样、Rebuffer、FIR、IIR、Biquad、延迟和常用滤波器。支持自定义组件，可以将编辑内容保存成一个组件。

组件包含：

+ 独立可编译的 C/C++ 源码，或dll库，接口统一
+ metadata，包括：
-- 输入输出端口定义
-- 参数、内存、延迟和实时属性声明

组件不得自行创建设备、线程或通信链路。
