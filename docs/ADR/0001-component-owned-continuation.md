# ADR-0001：Task 启动直接入口，组件自主续调

- 状态：已接受，历史补录
- 决策日期：2026-11-04（依据已有设计文档）
- 记录日期：2026-11-09
- 关联：[ADR-0002](0002-drive-and-buffer-separation.md)

## 背景与问题

按拓扑表逐个调用组件无法表达组件内部有条件续调、重复交付小块，以及下游返回后
继续完成上游工作的真实算法结构。用户要求动态 Runtime 与生成代码采用同一调用语义，
不保留旧逐组件调度兼容路径。

## 决策

Task 只启动直接入口。组件通过 ABI v6 的续接接口同步调用其直接下游，
自行决定何时续调、停止、重复调用或选择分支。框架不在组件成功返回后补调下游。
`execution_order` 用于编译分析、内存布局和展示，不是运行时调用表。

会合处不加入等待、每拍去重或额外调度：两条分支先后到达同一组件，就先后调用两次。
错误沿调用栈返回，停止后续兄弟分支；已经执行的计算不自动回滚。

## 考虑过的替代方案

- 保留拓扑调度器、为特殊组件追加回调：存在两套执行语义，不能满足统一模型。
- 会合屏障或每拍去重：改变算法的调用次数、先后顺序和数据可见性，拒绝采用。

## 影响与约束

组件必须主动调用续接接口。实时 process 不分配内存、阻塞或做宿主 IO。
续接上下文只在当前调用栈有效，不可跨线程保存。跨 Task 数据仍需要明确的数据桥，
调用链不自动赋予共享状态并发安全。

## 演进与落实

2026-11-04 的已有设计文档记录 ABI v6 首轮落地。Runtime 与生成 C 共用
`orpheus_chain.h`；不兼容旧 ABI DLL，组件需重建。
2026-11-06 的入口显示与传播更新另见 ADR-0002，不取代组件自主续调原则。
