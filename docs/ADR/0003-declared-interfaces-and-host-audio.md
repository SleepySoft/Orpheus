# ADR-0003：完整接口契约、端口宿主访问与按需显露

- 状态：已接受
- 决策日期：2026-11-09
- 记录日期：2026-11-09
- 关联：[ADR-0001](0001-component-owned-continuation.md)、[ADR-0002](0002-drive-and-buffer-separation.md)

## 背景与问题

参数面板曾隐藏部分 readback 参数，并遗漏仅在 C 注册的宿主 `samples` 存储。
公开配置参数被自动当作控制输入，混淆了配置公开、运行期控制能力和画布表现。
宿主音频数据又分裂为独立 samples 资源和图内输入，宿主输入模式甚至拒绝上游连接。

用户确认：组件定义应像 DLL 导出表一样完整描述外部契约；参数页供完整审查，
用户只在互联时显露接口；音频数据采用专门的端口表现。

## 决策

1. **声明是外部契约，C 是实现。** 参数、可访问数组/状态和命令必须在组件定义中有对应声明。
   不自动公开任意私有内存；配置不保存每拍 PCM。
2. **每个数据端口独立描述签名。** 一个组件可有多个不同输入/输出；
   连线检查源输出与目标输入，不要求全组件使用同一格式、通道数、块长或速率。
   转换由算法实现，不隐式插入格式、通道或采样率转换。
3. **宿主访问是端口的一种数据来源/访问方式。** 端口用 `host_binding`
   关联已声明 BULK 存储和交付状态；不是另外创建一条不可见音频链。
   可写输入未连上游时允许宿主交付；已连上游时使用上游数据，拒绝宿主写入。
   一个输入只有一个供数者，不设计隐式优先级或宿主覆盖。
4. **访问与显露分离。** 参数页完整展示已声明资源；未显露仍可审查和按权限访问。
   画布按需显露，已连接/已导出接口保持可见。显露是布局事实，不是算法参数。
   显露不升级 `bindable`、`control_source`、访问权限或更新策略。
5. **readback 不等于只读。** 用显式 `access` 描述权限，用 kind 描述用途；
   复合参数公开也不自动授权运行期控制连接。
6. **保持独立驱动。** 完整块交付只改变数据及状态，不触发执行。
   首轮宿主音频访问是 caller-serialized 的交错 f32 完整块协议，不宣称跨线程安全。

## 考虑过的替代方案

- 为每个算法增加同名 `samples` 参数：重复已有端口契约，也不能描述多个不同端口。
- 宿主 Buffer 与音频输入分别公开：制造两套概念、存储与连线难以审查。
- 连接上游后允许宿主覆盖：引入不透明的写入仲裁和时序错误，拒绝采用。
- 显露即自动 bindable，或隐藏即禁止访问：把视图选择误作权限/算法语义，拒绝采用。

## 影响与约束

`host_binding` 的启用条件只引用重启生效的配置参数，编译后不随实时参数偷偷改变。
绑定存储的有效形状、类型与状态必须和运行注册一致；容量不等于有效长度。
`host_audio` 的 `in` 可在宿主供数与上游供数之间随重新编译切换；
`buffer_source` 仍是宿主填充输出 Buffer 的驱动源，不额外增加算法输入或 Task。

音频端口的宿主绑定不承诺零拷贝。组件可保留必要的内部存储/复制，但外部只审查
同一个逻辑端口及其存储绑定；不把内部存储实现泄漏为另一套接口。

## 演进与落实

2026-11-09：新增 manifest/schema/plan 的宿主端口绑定和逐端口签名；
把 host_audio/buffer_source 的 samples、交付状态和读写能力补入声明。
动态与生成路径增加按节点/端口访问，旧逐实例便捷 API 转发统一入口，不保留另一套缓冲实现。
参数页、按需显露及保存重载同期实施；具体交付和验证结果见实施日志。

2026-11-09（界面组织补充）：参数侧栏可收起并移入独立浏览器窗口，而不是复制一份配置状态。
独立窗口通过同一 React 树更新当前选中节点，关闭后收回侧栏；参数、Buffer 和端口可按组折叠，
大窗口自适应分列。采用浏览器窗口以支持多显示器和原生缩放，不引入另一套参数访问或保存协议；
窗口管理不属于工程部署事实，浏览器拦截时明确报告，不丢失原面板。

边界：完整审查覆盖已有声明，不声称已经审计并补录所有历史组件 C 私有/注册资源。
任意音频端口的外部观测、异步 PCM 采集和 Bridge 上的原子音频提交协议
不能因本次端口绑定而视为已实现，后续扩展应另行记录决策与验收。
