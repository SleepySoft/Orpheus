# ADR-0004：初始化配置与运行期接口分离，公开参数不自动显露

- 状态：已接受
- 决策日期：2026-11-09
- 记录日期：2026-11-09
- 部分取代：[ADR-0003](0003-declared-interfaces-and-host-audio.md) 中“已导出参数强制显露”的规则

## 背景与问题

复合组件的公开参数通过 `maps_to` 映射到内部参数，既可能是初始化配置，也可能是运行期调参入口。
此前画布将所有公开映射加入强制显露集合，形成大量参数行，并禁止用户隐藏，即使没有实际连线。
静态配置还被画入橙色控制区，有导出引线但没有控制方块，混淆了公开配置与控制连接。

## 决策

1. **公开映射与画布显露独立。** 对外公开不自动绘制内部参数，也不锁定显露选择。
   取消“图上显露”不删除 `maps_to`、参数定义或值，不移除外层配置入口。
2. **参数默认不显露。** 仅用户明确选择或存在实际控制连线时显示。
   真正已连接的参数仍锁定可见；已有显露选择保持，不批量重写工程布局。
3. **初始化配置与运行期接口分开呈现。** `restart_required` 或 `affects_signature`
   参数归入初始化配置，完整面板可编辑；主动显示时采用独立灰色区域与“初始化”标记，
   不生成运行期控制方块或橙色控制导出引线。
4. **生命周期限制不因 UI 选择改变。** 启动前注入配置，再编译/prepare 并运行；
   `restart_required` 指运行后更改需重新准备，不是初始化赋值也需要额外重启。
   tuner 不能通过运行期写接口绕过初始化策略。
5. **能力不从公开、可写或显露推断。** 运行期方块仍由显式 `bindable` /
   `control_source` 及权限决定；旧实际连线保留不可连接锚点，避免幽灵线，
   不因此授权初始化参数的新控制连接。
6. **数据端口规则不变。** 已连接音频端口和复合组件导出音频端口仍强制可见。
   Buffer 的主动显示独立于参数行，不因参数隐藏而丢失，也不重复绘制。

## 考虑过的替代方案

- 删除静态参数的公开映射：改变外层初始化配置能力，且为清理画布删除契约，不采用。
- 仅隐藏初始化参数，继续强制绘制所有运行期公开参数：无连线的公开参数仍铺满画布，不采用。
- 给全部公开参数补控制方块：将初始化配置错误升级为运行期控制连接，不采用。

## 影响与约束

参数页分为初始化配置、运行期参数、观测/交付状态，继续完整审查已声明接口。
复合公开参数列表注明生命周期类别，供外层配置和映射审查；画布只是按需展示。
同一参数的初始化值、更新策略、控制权限、公开映射和显露选择是不同事实。
只读组件定义的显示选择也属于工程布局，可在不修改定义的情况下调整；只读状态不锁定显示开关。

本轮不修改 manifest、布局格式、编译计划或 ABI，也不实现新的初始化注入、tuner 或重启协议。
既有配置/prepare 路径保持不变；图内算法参数和用户显露选择不被清理操作重写。
