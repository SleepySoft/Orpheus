# ADR-0006：端口配置优先，自适应不覆盖配置，失配连线显式标红

- 状态：已接受
- 决策日期：2026-11-10
- 记录日期：2026-11-10
- 关联：[ADR-0005](0005-recursive-port-signature-source.md)

## 背景与问题

端口规格被整体遮盖为“解析中”，掩盖了已经声明的类型、样本格式和通道配置。
用户需要看到自己配置的两端规格，并自主修正错误，而不是让连接悄悄改写参数。
既有 WAV 输出采样率跟随逻辑甚至覆盖非零的显式配置，使错误连线看起来合法。

## 决策

1. 按字段区分配置与依赖。字面量、自身参数和显式 Task 表达式确定的值是配置，
   不得因为上游不同而改写；`in:` 表达式表示明确的输入依赖。
   省略块长或采样率继续采用既有上下文继承语义，不等于允许覆盖其它显式字段。
   不把支持不同处理块长的组件误称为自动识别或转换音频格式。
2. WAV 输出的 `sample_rate=0` 明确表示跟随输入，缺省为 0，参数界面说明这一含义。
   非零采样率是用户配置，不再自动纠正。推导只发生在编译内存副本中，
   工程仍保留 0，不把派生采样率写回用户文件。
3. 已知配置立即显示。界面只能直接读取字面量、单个参数及其声明默认值，
   不新增算式求值器；复杂表达式、引用和继承值仍由编译器唯一事实源解析。
   校验进行中不应遮盖已经确定的配置。
4. 编辑态与编译共用端口差异规则，检查类型、样本格式、通道数、音频采样率、
   交付块长，以及非音频数组的长度、布局与帧结构。
   合流和跨 Task 桥按消费者实际交付长度检查，不把合法桥接误判为普通块长失配。
5. 预览保留两端配置和连线，逐连接返回差异；复合边界映射回当前视图端点。
   对应数据线标红，悬停显示字段、源值、目标值和手动修改提示；
   用户修正配置后重新校验并恢复正常颜色。推导失败明确标记错误，不伪装成匹配。
   正式编译拒绝失配，不增加静默重采样、重排、填充、截断或广播。

## 考虑过的替代方案

- **连接时把目标配置改成源配置**：隐藏真实工程错误，拒绝采用。
- **失配时删除或拒绝所有连线**：用户无法保留编辑现场并对照修正。
- **前端复制编译器推断规则**：产生第二份事实源，拒绝采用。
- **把所有端口字段改为固定 Task 规格**：破坏既有明确的多速率、分帧与桥接语义。

## 影响与约束

- 配置不匹配的旧 WAV 工程现在会明确报错，须由用户修改配置或选择 0 跟随输入；
  不批量修改研究工程来让验证通过。
- 连接诊断和显示状态是派生数据，不进入 YAML，不改变 ABI、调用链或运行时数据面。
- 原子端口配置和复合外层约束各自保留；外层约束冲突仍报告真实引用与声明差异。
- 本次不承诺所有继承字段瞬时解析，不通过前端猜值掩盖后端加载耗时。

## 演进与落实

共用连接差异比较，预览报告、编译拒绝；显式 WAV 自动模式取代无条件参数覆盖。
前端立即呈现可直接读取的配置，数据线使用后端逐连接诊断标红。
