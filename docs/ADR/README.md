# 架构决策记录（ADR）

ADR 记录重要设计的**背景、选择、理由、影响和演进**，不是任务清单，也不代替实现说明。
当前行为见 HOW 参考文档；验证与实际交付见实施日志。三者应相互链接。

## 维护规则

1. 改变执行模型、ABI、接口/资源模型、工程格式或用户操作语义时，随实现新增或更新 ADR。
2. 编号递增，不重用。状态使用“提议 / 已接受 / 已拒绝 / 已取代”。
3. 已接受的核心决定不静默改写。后续改变另写 ADR，在旧记录注明取代关系，
   在新记录说明改变原因；不改变核心决定的实现进展追加到“演进与落实”。
4. 分开记录“设计已接受”和“实现已验证”。未实现部分明确列出，不用 ADR 状态替代验收。
5. ADR、相关 HOW 文档与实施日志和代码在同一任务中维护；记录实测证据，
   不把计划中的测试写成已通过。研究工程自身的决定在对应仓库记录，主仓只链接必要边界。
