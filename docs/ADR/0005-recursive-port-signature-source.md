# ADR-0005：沿端口引用递归解析，编译器作为签名唯一事实源

- 状态：已接受
- 决策日期：2026-11-10
- 记录日期：2026-11-10
- 关联：[ADR-0003](0003-declared-interfaces-and-host-audio.md)、[ADR-0004](0004-parameter-lifecycle-and-visibility.md)

## 背景与问题

复合端口通过 `maps_to` 引用内部端口，却曾只在界面读取当前层声明：
省略格式时显示“格式未声明”，复杂表达式显示“未确定”，块长还会回退到工程全局值。
补齐每层 YAML 或在 JavaScript 复制求值器都会产生第二份事实源；
不同实例的公开参数、Task 上下文、上游速率和可变端口尤其容易失配。

## 决策

1. 端口是引用，而不是签名副本。复合端口可以仅声明 `id/direction/maps_to`，
   沿引用递归到原子实例；每层公开初始化参数先注入直接子实例，再继续展开。
   同一定义的不同实例分别解析，不缓存为一个全局签名。
2. 端口展开、默认参数、表达式、Task 时钟、采样率与块长传播复用编译器的公共解析阶段。
   每个端口独立返回方向、数据类型、样本格式、通道数、帧数和采样率，
   不假设一个组件只有一份输入/输出音频配置。
   省略时钟源采样率时仍继承 Task，不因补齐其它参数默认值改变这一语义。
3. 外层显式签名字段是约束，不代表隐式格式、通道或速率转换。
   约束与实际引用冲突时，编辑预览保留真实签名并报告具体路径、字段和值；
   正式编译拒绝冲突。既有显式声明保留，不批量改写用户工程。
4. 编辑态使用只读快照 API，不要求先生成可执行计划或连接所有时钟。
   先按数据连通分量展开，再共享已解析的 Task 时钟上下文；
   不可解析的分量报告错误，不遮蔽其它可解析分量。
   未知组件、坏引用、循环、非法表达式和未知 Task 不伪造成功签名。
5. 界面只呈现解析结果、最终原子引用来源或明确的等待/失败状态；
   不再用本地简单表达式求值或全局块长冒充有效签名。
   画布、宿主 Buffer 摘要、完整参数页和公开音频候选使用同一份结果。
   复合定义视图使用该定义的公开默认值，不任取某个实例覆盖值。
6. 派生签名、来源和诊断不写回各层 YAML、布局或算法参数。
   保存复合定义不再凭空补 `audio/f32`；原子 manifest 的必填类型规则不变。
   叶子端口的宿主存储绑定不自动提升为复合组件自身的访问能力。

## 考虑过的替代方案

- **每层复制完整格式**：容易漂移，实例覆盖后仍可能失真。
- **前端递归和表达式求值**：重复编译器规则，无法可靠保持传播、分帧与可变端口一致。
- **先完整编译再显示**：编辑中的断线、占位和无时钟图无法审查接口。
- **遇到错误回退到 f32 / 工程块长**：把错误伪装成已确定事实，拒绝采用。

## 影响与约束

- `POST /api/projects/{name}/interfaces` 接收未保存的 `document` 与 `view_key`，
  使用真实工程路径解析 imports/resources，不调用保存或生成执行计划。
- UI 请求防抖、取消并隔离迟到响应。拖动、接口显露和观测更新不触发重新解析。
- 编辑态解析不是执行合法性认证；例如执行循环、驱动与平台约束仍由正式编译验证。
- 不解析的分量仍可编辑；请求失败会显示原因，不能继续展示过期签名为当前事实。

## 演进与落实

已提取编译器共享的端口与块长解析阶段，复用递归展开的最终端点；
增加实例约束保留、只读 API 和 UI 接入。默认参数注入及无上游输入表达式使用同一套规则。
